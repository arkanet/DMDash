Use DarkMesh iOS and DMDash without guesswork

DarkMesh iOS packages the DMDash dashboard in a native iPhone shell with native Bluetooth. This guide focuses on the workflows a normal operator actually needs: installing the app, connecting hardware, sending messages, reading the map, managing settings, and using the DarkMesh dashboard tools.

Before you start

  • On iPhone, use DarkMesh iOS: the native shell uses iOS Bluetooth instead of browser Bluetooth APIs.
  • In desktop browsers, some automation features run only while the tab stays open and connected.
  • Web Bluetooth and Serial require a browser that supports Web Bluetooth or Web Serial. Chrome and Edge are the safest choices.
  • On iPhone, if you use the web client instead of the native app, open it with Bluefy or another iOS wrapper that supports Web Bluetooth. Safari is not enough for BLE.
  • HTTP(S) and Network TCP to bridges or gateways work only when DMDash itself is served from a local LAN server, not from an external domain.
  • Different devices can show different settings tabs because DMDash hides sections the target firmware or role does not support.
Good default path: install DarkMesh iOS first on iPhone, connect the radio from Connections, confirm the node appears in the sidebar, then move to Messages, Map, Dashboard, and Settings.

Install DarkMesh iOS on iPhone

This flow uses AltServer and AltStore to install the DarkMesh iOS .ipa on an iPhone. Follow the steps in order.

DarkMesh iOS Download darkmesh.ipa.

Initial setup, first time only

Install AltServer on your Windows or Mac computer, then use AltServer to transfer AltStore to the iPhone.

Windows

Download and install AltServer from altstore.io. Also install the official desktop versions of iTunes and iCloud, not the Microsoft Store versions.

Mac

Download AltServer, open it, and grant the requested Accessibility permissions.

  1. Connect the iPhone to the computer with a cable.
  2. Click the AltServer icon in the computer menu bar or tray.
  3. Select Install AltStore > [iPhone Name].
  4. Enter your personal Apple ID credentials. Apple uses them to generate a local free signing certificate.

Authorize on iPhone

AltStore appears on the Home screen, but iOS will not open it until the developer profile is trusted.

  1. Open Settings > General > VPN & Device Management.
  2. Under Developer App, tap the email address of your Apple ID.
  3. Tap Trust [Your Email], then confirm with Trust.
  4. On iOS 16 or later, open Settings > Privacy & Security > Developer Mode.
  5. Enable the switch, restart the iPhone when prompted, unlock it, and confirm with Turn On.

Install the app from the IPA file

  1. Download the DarkMesh iOS .ipa from the button above and save it in the iPhone Files app.
  2. Keep the iPhone connected to the computer or on the same Wi-Fi network as the computer running AltServer.
  3. Open AltStore on the iPhone.
  4. Go to the My Apps tab at the bottom.
  5. Tap the + button in the top-left corner.
  6. Select the DarkMesh iOS .ipa file.
  7. Wait while AltStore re-signs the app with the Apple ID and installs it on the Home screen.

Daily use and 7-day refresh

  • Daily use: open DarkMesh iOS normally from the Home screen icon.
  • Refresh: the free signing license expires every 7 days. Open AltStore, go to My Apps, and tap Refresh All while the iPhone is connected to the computer or on the same Wi-Fi network as the computer running AltServer.
  • AltStore can also try background refresh, but AltServer still needs to be reachable.

Use the web client with Bluefy

The video flow uses Bluefy as a Web Bluetooth browser wrapper for iPhone. It is not a TCP bridge on the LAN: it lets the DMDash site open the iOS Bluetooth picker and talk directly to the node. This path is also useful on older iPhones where App Store blocks the official Meshtastic client because of an iOS requirement.

  1. Install and open Bluefy on the iPhone.
  2. When prompted, allow Bluefy to use Bluetooth and Notifications.
  3. In the Bluefy address bar, open https://dmdash.arkantiko.com.
  4. From the Bluefy menu, you can enter full screen mode to make DMDash feel closer to a native app.
  5. In DMDash, press Add Connection and choose the Bluetooth tab.
  6. Press Select device, pick the node in the iOS Bluetooth picker, and keep the option enabled for future or background connections to this site.
  7. When the name is filled as BT: [Node name], press Save connection.
  8. If the connection does not start automatically, press Connect on the new card.
  9. Wait for Configuring device to finish while DMDash downloads nodes, configuration, and previous messages.
  10. When Map or Nodes opens and the top status turns green, you can use messages, map, node details, traceroute, and contextual menus.
Upgrade from the YouTube video: the original flow used the official Meshtastic app only for initial pairing, then disconnected it to free the Bluetooth channel. With the updated Bluefy flow, and with DarkMesh iOS, you no longer need to install it: device selection and pairing start from the iOS Bluetooth picker.
Network bridges: if you have an always-on gateway or local bridge on the LAN, use Network TCP or HTTP(S) in Connections only from a copy of DMDash served on the same local network. This path does not work from external domains and is different from Bluefy.

Connect your node

Option 1: Native iOS Bluetooth

In DarkMesh iOS, choose Bluetooth from the Connections page. Device selection goes through the iOS picker, and the connection is saved for later launches.

Option 2: HTTP(S)

Choose HTTP(S) when the node or gateway is already reachable on the network and you are using DMDash from a local server on the same LAN. DMDash includes a connection test before saving the entry.

Option 3: Network TCP

Use Network TCP when you have a Meshtastic TCP endpoint on the LAN and the DMDash client is served from the LAN. Do not use this mode from the public domain: DMDash must run from a local host, such as a computer or server on the same network as the gateway.

Option 4: Web Bluetooth

Use this when the node is nearby and your browser supports Web Bluetooth. On iPhone, use Bluefy: the iOS picker asks you to select the device and authorize future background connections.

Option 5: Serial

Use this when the node is connected by USB and your browser supports Web Serial.

Reconnect: if a BLE or Serial connection drops, the app tries to restore it before asking you to pick the device again. If retry fails, return to Connections and pair again.
If HTTP(S) fails: when the endpoint uses a self-signed certificate, open it once in a separate tab, accept the certificate warning, and then test the connection again from DMDash.

Understand the main areas

Dashboard DarkMesh-only workflows: notifications, traceroute history, scheduled sends, distress beacon, hunt forwarding, `.dmdb` import/export, pruning.
Connections Radio pairing, saved connections, retry, default connection, native iOS BLE, Network TCP, HTTP(S), web Bluetooth, and Serial.
Messages Direct and broadcast chat, replies, mentions, reactions, emoji picker, message status, inline node status text.
Map Node markers, filters, popup cards, environment metrics, neighbor lists, and traceroute overlays.
Nodes Sortable table, filters, signal view, encryption status, favorites, and one-click node details.
Settings Local configuration split into Radio, Device, and Module sections.
Remote Admin Remote read/write workflow for compatible nodes, again split into Radio, Device, and Module sections.
Debug Technical panel from the command menu for inspecting events, runtime state, and diagnostic details.

Use the DarkMesh dashboard

Notifications

The dashboard collects operational notifications, including low-battery events and schedule-related events.

Traceroute history

Recent traceroutes are collected in one place so you can inspect path quality without opening the raw packet stream.

Scheduled messages

DMDash supports recurring message rules. The current build exposes the rule editor in the dashboard workflow, where you can define destination, recurrence, and message text.

Distress beacon

You can configure a repeated emergency-style broadcast or direct send, optionally including location semantics used by DarkMesh.

Hunt forwarding

The dashboard can validate and enable remote or local hunt forwarding modes when your workflow requires them.

Mesh Stats and compression

Mesh Stats tracks text-compression savings and lets you choose modes compatible with legacy DarkMesh firmware or DarkMesh 2.7.26+ app-side compression.

Import, export, and maintenance

`.dmdb` import/export and pruning tools are available from the dashboard, making it easier to move contact sets or clean stale node data.

Work with messages

  • Broadcast chats and direct chats are both supported.
  • Replies can be created quickly, and reply previews can jump back to the original message.
  • Mentions are highlighted and autocomplete excludes the local node to avoid self-mentions.
  • Emoji reactions and message delivery state are visible in the thread.
  • Node avatars in the thread open the node details dialog.
  • When a node has a Status Message, it appears after the node name and before the timestamp in the chat header line.

Read the map and node details

The map and node list are the fastest way to inspect node health. Clicking a marker or avatar opens a popup or details dialog with user, signal, environment, and neighbor information.

  • Favorites are marked directly in the avatar.
  • Status Message badges appear on avatars when a node currently publishes one.
  • The badge pulses until you open the map popup or the node details dialog, then it becomes steady.
  • The popup and dialog also display the full Status Message text when it exists.
  • Visual traceroute can be started from node popups and details to inspect the route.
  • When a node publishes power metrics, map and node details show available channel voltage and current.

Configure your device

Local settings are split into three areas so you do not have to understand the internal protobuf layout.

Radio LoRa, channels, and security-related sections.
Device User, device, position, power, network, display, and Bluetooth sections.
Module Telemetry, audio, canned messages, remote hardware, status message, traffic management, and other firmware-dependent modules.
Save operations are grouped. DMDash can collect multiple changes, then commit them together.

Operate Remote Admin

  1. Open a node from the map or node list.
  2. Choose the Remote Admin action for that node.
  3. Move through the Radio, Device, and Module sections.
  4. If a subsection is empty, use Refresh and wait for the remote response.

Remote Admin tabs are also firmware-aware, so unsupported subsections stay hidden instead of showing a broken form.

Status Message workflow

Status Message is now a full workflow rather than just a settings field.

  • Set it from Settings > Module > Status Message or from the equivalent Remote Admin module tab.
  • When a node has a status, the text appears in the map popup and the node details dialog.
  • The same text also appears in message threads after the node name.
  • Avatars show a chart badge while the status is unread, then keep a steady badge after you open popup or dialog.

Limitations and troubleshooting

Some settings tabs are missing

This usually means the current firmware or node role does not support them.

Bluetooth or Serial options are disabled

Your browser probably lacks the required Web API support or secure-context permissions.

AltStore or DarkMesh iOS will not open on iPhone

Confirm that the developer profile is trusted in iOS and, on iOS 16 or later, that Developer Mode was enabled and the restart completed.

DarkMesh iOS expires after a few days

That is expected with free AltStore signing. Run Refresh All within 7 days while AltServer is reachable from the phone.

Automation did not trigger

Keep the DMDash tab open and the device connected. Browser-side automations do not survive like Android foreground services.

HTTP(S) cannot connect

First confirm that DMDash is open from a local LAN server. If the endpoint uses a self-signed certificate, open it directly in the browser and accept the certificate warning.

Best practice: treat DMDash as a rich browser operator console. For long-lived unattended workflows, remember that the browser session is part of the runtime.
